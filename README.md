# ПОС — Преподавательская Оценка Студентов

Консольное приложение на C# / .NET 10 для учёта оценок, которые преподаватель выставляет студентам по критериям рубрикатора. Проект построен по DDD, архитектура — Clean Architecture в учебном варианте, внедрение зависимостей через Microsoft.Extensions.DependencyInjection.

## Используемые технологии

- Язык и платформа: C#, .NET 10.
- DI-контейнер: Microsoft.Extensions.DependencyInjection.
- Хранилище: JSON-файл `pos-data.json` (System.Text.Json), экспорт итогов в CSV.
- Тестирование: xUnit, coverlet.collector.

## Возможности приложения

- Студенты: добавить, посмотреть список, удалить.
- Критерии рубрикатора (название, максимальный балл, вес): добавить, посмотреть, удалить.
- Оценки: выставить, исправить, отменить, посмотреть оценки студента (комментарий и дата сохраняются).
- Итог студента с выбором режима расчёта.
- Экспорт итогов всех студентов в CSV.
- Демонстрационный сценарий (пункт 6 меню), который проходит весь путь: студенты и критерии → оценки → итог → экспорт.

Основные правила:

- Балл оценки лежит в диапазоне от 0 до максимума критерия. Выставить 12 баллов из 10 нельзя.
- Оценку можно выставить только по критерию из рубрикатора.
- По одному критерию у студента одна оценка. Её можно исправить или отменить.
- Критерий нельзя удалить, пока по нему есть оценки.
- Названия критериев уникальны без учёта регистра и внешних пробелов.
- Итог не хранится отдельной цифрой, а вычисляется из оценок и рубрикатора: `Σ(балл / максимум × вес) / Σ(вес) × 100`, округление до двух знаков.
- Режимов расчёта два: «только выставленные оценки» (критерии без оценки не участвуют) и «невыставленные оценки считать нулевыми».

## Архитектура

Выбрана **Clean Architecture**. Правило зависимостей: код внутреннего круга ничего не знает о внешних. Домен не знает о консоли, JSON и CSV. Сценарии объявляют интерфейсы (порты), а внешние слои их реализуют.

| Круг Clean Architecture | Проект | Что внутри |
|---|---|---|
| Entities (бизнес-правила предприятия) | `POS.Models` | `Student`, `Rubric`, `Criterion`, `Evaluation`, `Score`, `Weight`, `Grade`, `EvaluationFactory`, `GradeCalculationService`, стратегии расчёта, `DomainException` |
| Use Cases (правила приложения) | `POS.UseCases` | обработчики сценариев (`SetEvaluationHandler`, `CalculateGradeHandler`, …), DTO, порты `IStudentRepository`, `IRubricRepository`, `IGradeExporter` |
| Interface Adapters | `POS.Infrastructure`, `POS.Presentation` | `JsonStudentRepository`, `JsonRubricRepository`, `CsvGradeExporter` с маппингом домен ↔ хранимые DTO; `ConsoleMenu`, `DemoScenario`, `POSFacade` |
| Frameworks & Drivers, composition root | `POS.Host` | `Program.cs`, DI-контейнер, сборка графа зависимостей |

Стрелка зависимостей (всё направлено внутрь):

```
POS.Host ──► POS.Presentation ──► POS.UseCases ──► POS.Models
   │                                   ▲
   └──────► POS.Infrastructure ────────┘
```

- `POS.Models` не ссылается ни на один проект.
- `POS.UseCases` зависит только от домена и объявляет порты.
- `POS.Infrastructure` реализует порты. Хранимые DTO и работа с JSON остаются внутри этого проекта (`internal`).
- `POS.Presentation` знает только сценарии. Репозитории и CSV он не видит.
- `POS.Host` — единственное место, где порты связываются с реализациями.

## Карта DDD

**Ubiquitous Language.** В коде используются слова предметной области: студент (`Student`), критерий (`Criterion`), рубрикатор (`Rubric`), оценка (`Evaluation`), балл (`Score`), вес (`Weight`), итог (`Grade`).

| Понятие | Роль | Почему |
|---|---|---|
| `Student` | Entity, корень агрегата | Имеет идентичность (`Guid`), хранит свои оценки, сам охраняет «одна оценка на критерий» |
| `Rubric` | Entity, корень агрегата | Единственный набор критериев курса. Охраняет уникальность названий и отвечает на вопрос «есть ли такой критерий» |
| `Criterion` | Entity внутри `Rubric` | Имеет идентичность, неизменяем после создания |
| `Evaluation` | Value Object | «Студенту по критерию поставили балл». Определяется значениями, создаётся только через фабрику, при создании проверяет `score ≤ max` |
| `Score`, `Weight`, `Grade` | Value Object | Самовалидирующиеся значения: балл ≥ 0, вес > 0, итог в диапазоне 0–100 |
| `GradeCalculationService` | Domain Service | Правило итога не принадлежит ни студенту, ни рубрикатору. Сервис считает формулу по весам и нормирует результат |
| `IStudentRepository`, `IRubricRepository` | Repository (порт) | Хранение вынесено из домена. Один репозиторий на агрегат |

**Инварианты и где они охраняются:**

| Правило | Где |
|---|---|
| Балл ≥ 0 | `Score` |
| Балл ≤ максимума критерия | `Evaluation` |
| Оценка только по критерию из рубрикатора | `EvaluationFactory` через `Rubric.GetRequired` |
| Одна оценка на критерий у студента | `Student.AddEvaluation` |
| Вес > 0, максимум > 0, название не пустое | `Weight`, `Criterion` |
| Названия критериев уникальны | `Rubric.Add` |
| Итог согласован с текущими оценками | `GradeCalculationService` считает итог заново при каждом запросе |

**Границы агрегатов.** `Student` и `Rubric` — два отдельных агрегата, они ссылаются друг на друга только по идентификатору. Правило «нельзя удалить критерий, по которому есть оценки» затрагивает оба агрегата, поэтому оно проверяется в сценарии `RemoveCriterionHandler`, а не внутри одного из них.

**Осознанное решение.** `Evaluation` хранит копию максимального балла критерия на момент выставления. Критерии неизменяемы, поэтому копия не расходится с рубрикатором, а оценка остаётся самодостаточной и сама проверяет диапазон.

## Паттерны GoF

| Группа | Паттерн | Где | Какую боль закрывает |
|---|---|---|---|
| Порождающий | **Factory** | `EvaluationFactory` | Единая точка создания оценки. Конструктор `Evaluation` внутренний, поэтому создать оценку в обход фабрики нельзя (кроме восстановления из хранилища через `Evaluation.Restore`). Фабрика находит критерий в рубрикаторе, проверяет диапазон и ставит дату. Время берётся из `TimeProvider`, поэтому оно подменяется в тестах |
| Структурный | **Facade** | `POSFacade` | Консоль работает с одним объектом вместо тринадцати обработчиков. Меню и демонстрационный сценарий не знают о составе сценариев, а при добавлении нового сценария меняется фасад, а не весь UI |
| Поведенческий | **Strategy** | `IGradeCalculationStrategy`, `GradedCriteriaStrategy`, `MissingAsZeroStrategy` | Правило «какие критерии участвуют в итоге» сменяется без изменения Domain Service. Формула остаётся в сервисе, а стратегия решает только, как трактовать критерий без оценки |

Выбор стратегии по ключу выполняет `GradeStrategyResolver`: он получает из DI все зарегистрированные стратегии. Чтобы добавить новый режим, достаточно написать класс и добавить одну строку регистрации. Меню строит список режимов из описаний стратегий, поэтому его менять не нужно.

## Тестирование

Основные группы тестов:

- `ScoreTests`, `WeightTests`, `GradeTests` — самовалидация value object.
- `RubricTests` — уникальность названий (без учёта регистра и пробелов), удаление, поиск критерия.
- `EvaluationFactoryTests` — диапазон баллов, граничные значения 0 и максимум, отказ по критерию вне рубрикатора, обработка комментария.
- `StudentTests` — одна оценка на критерий, исправление и отмена.
- `GradeCalculationServiceTests` — взвешенный итог, оба режима, округление, пересчёт после исправления оценки, пустые данные.
- `UseCaseTests` — сценарии на in-memory репозиториях: отклонённая оценка не сохраняется, критерий с оценками не удаляется, выбор стратегии.

Ключевые тесты:

- `EvaluationFactoryTests.Create_WithScoreAboveMaximum_ThrowsException` — нельзя поставить 11 из 10.
- `EvaluationFactoryTests.Create_WithCriterionNotInRubric_ThrowsException` — нельзя оценить критерий, которого нет в рубрикаторе.
- `UseCaseTests.SetEvaluation_ScoreAboveMaximum_IsRejectedAndNothingStored` — отклонённая оценка не попадает в хранилище.
- `GradeCalculationServiceTests.Calculate_ChangesWhenEvaluationIsUpdated` — итог согласован с текущим набором оценок.

## Консольное меню

| Пункт | Действие |
|---|---|
| 1 | Студенты: добавить, показать, удалить |
| 2 | Критерии: добавить, показать рубрикатор, удалить |
| 3 | Оценки: выставить, исправить, отменить, посмотреть оценки студента |
| 4 | Итог студента (с выбором режима расчёта) |
| 5 | Экспорт итогов в CSV |
| 6 | Демонстрационный сценарий |
| 0 | Выход |

Студенты и критерии выбираются по номеру из списка, GUID вводить не нужно. Числа можно вводить и с точкой, и с запятой.

Демонстрационный сценарий показывает:

1. Создание студентов и критериев.
2. Выставление оценок.
3. Отклонение недопустимых действий: 12 баллов из 10, отрицательный балл, критерий вне рубрикатора, повторная оценка по критерию.
4. Исправление и отмену оценок.
5. Итоги в обоих режимах расчёта.
6. Экспорт в `demo-grades.csv` и вывод содержимого файла.

Демо-данные в конце удаляются из хранилища, поэтому сценарий можно запускать повторно. Файл экспорта остаётся.

## Возможности расширения

- **Новый режим расчёта итога.** Класс, реализующий `IGradeCalculationStrategy`, и строка регистрации в `AddUseCases`.
- **Другое хранилище.** Новая реализация `IStudentRepository` и `IRubricRepository` и замена регистрации в `AddInfrastructure`. Домен и сценарии не меняются.
- **Другой формат экспорта.** Новая реализация `IGradeExporter`.
- **Импорт ведомости.** Новый сценарий в `POS.UseCases` и порт для чтения. Подойдёт Template Method: общий каркас, разный разбор CSV и JSON.
- **Пересдачи, апелляции, несколько курсов.** Расширяют агрегат `Student` и добавляют идентификатор курса к `Rubric`. Остальные слои это не затрагивает.
- **Другой интерфейс.** Бизнес-правила не зависят от консоли, поэтому новый интерфейс подключается к `POSFacade` или напрямую к обработчикам.

## Запуск

Требуется .NET SDK 10.0. Команды выполняются из корня репозитория.

Запуск приложения:

```
dotnet restore POS.sln
dotnet run --project POS.Host/POS.Host.csproj
```

Запуск тестов:

```
dotnet test POS.sln
```

Тесты с отчётом покрытия:

```
dotnet test POS.sln --collect:"XPlat Code Coverage"
```

Данные сохраняются в `pos-data.json` в рабочей директории приложения. Файл создаётся при первом сохранении. CSV-экспорт записывается в файл, имя которого вводится в меню (по умолчанию `grades.csv`).
